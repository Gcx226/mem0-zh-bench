## 受控实验：检索侧净效果（固定记忆库 A/B）

端到端跑分受抽取 LLM 非确定性干扰（整段会话偶发返回空）。为隔离检索侧效果，
对**同一份记忆库**用 PUT 原文重建索引，在不同预处理/匹配语义下只测检索：

| 题型 | 原版（spaCy+AND） | jieba 分词 | jieba+OR 语义 |
|---|---|---|---|
| 总体 | 89.8% | 89.8% | 89.8% |
| 单跳事实 | 86.4% | 86.4% | 86.4% |
| 多跳组合 | 95.5% | 95.5% | 95.5% |
| 时间推理 | 81.8% | 81.8% | 81.8% |
| 知识更新 | 95.5% | 95.5% | 95.5% |

诊断链：原版 spaCy 不切中文 → BM25 全零；仅换 jieba 后 BM25 仍全零，
因为 plainto_tsquery 是 AND 语义，自然问句的词元不可能全部命中同一条记忆；
改 OR（to_tsquery 以 | 连接）后关键词通道才真正参与打分（explain 明细 bm25 0→0.034）。

**未命中归因**：对 jieba+OR 组 9 道 recall 未命中题逐题核查，9/9 的证据事实
根本不在记忆库中（写入侧抽取失败），0 道属于"在库但搜不到"。即当前语料下检索已饱和，
bge-m3 语义向量能搜到所有存在的证据；recall 损失与端到端失分的瓶颈完全在写入侧
（整段会话被抽取 LLM 判空、新旧状态共存不 UPDATE）。

## 方法学说明与已知局限

1. **抽取召回率**按事实 token 在埋入会话后的记忆快照中是否出现计算；superseded 事实按埋入时点计入。token 匹配是近似，语义改写可能漏判。
2. **检索 recall@5**：top5 记忆中任一命中证据事实 token 即算命中；拒答题不计入。
3. **裁判校准**：两组结果均用同一裁判提示词重判（含"非拒答题答不知道判错"、"时间语义等价判对"规则），见 rejudge.py。
4. **抽取非确定性**：mem0 的 LLM 抽取偶发对整段会话返回空（观测到 s3/s4/s5 均有 0 条案例），单次运行存在噪声；更新链失败部分源于此。
5. **优化内容**：两处补丁——(a) BM25 预处理从 spaCy 英文词形还原换为 jieba 中文分词（含停用词过滤），add/search 共用；(b) pgvector 关键词匹配从 plainto_tsquery（AND）改为 to_tsquery OR 连接，ts_rank_cd 排序不变。均通过 docker cp + touch 热重载部署，不重启容器。
6. **端到端 optimized 组**仅含 jieba 补丁（OR 补丁在其后部署）；两组端到端差异主要由抽取非确定性主导，检索侧结论以受控实验为准。
7. **写入侧优化机制**：该版 mem0 的 V3 抽取流水线为 ADD-only（无 UPDATE/DELETE 决策，去重仅靠 MD5 精确匹配），新旧状态天然共存。中文抽取指令通过官方 prompt 参数（Custom Instructions，系统提示中声明为最高优先级）要求：以会话文本内日期为唯一时间锚点（覆盖系统注入的运行日期）、禁止对新个人信息返回空列表、事实自包含（带姓名与绝对日期）、状态更新显式写成含生效日期的当前态事实。
